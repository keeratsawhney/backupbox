# Changelog

All changes since this repository was forked from [Little Backup Box](https://github.com/outdoorbits/little-backup-box).
Every entry is a merged pull request; the pull request has the full description.

## 2026-10-25

### Android app, Bluetooth, OLED
- **#97 Previews like a file manager: fast, when a row or a file is seen**: no batch process after a backup (#95); the preview is made the moment it is needed and is fast: a JPEG is decoded at a fraction of its size (`lib_thumb_fast.py`, no full decode of a 24 MP photo), a raw file gives the preview the camera stored in it (exiftool), a video its first key frame; a preview made during an earlier backup (`tims`) is used as it is. ImageMagick is only the fallback. The Files list shows these previews again for the rows that are on screen (made once, then kept), opening a file shows a sharp 1600 px preview.
- **#95 No previews after a backup; a preview is made when a file is opened**: the thumbnails and the "Previews" step after a backup are off by default (`conf_BACKUP_GENERATE_THUMBNAILS`, also for a new installation); the update switches them off once on an existing box (it can be switched on again in the settings or per backup). The Files list makes no preview of its own: it shows a preview that already exists (earlier backups) and the file type otherwise; opening a file makes its preview (first and last pictures, or any). The list of the newest files on the home screen is gone with the Photos tab.
- **#93 File transfer mode on the touch screen**: while a network cable is connected (with an address) and the box shares its drives, the home screen shows a *File transfer mode* card (speed, `\\<box>\media`, `smb://<box>/media`, login) and a pill in the top bar. Before it was only a line in the System tab. The Wi-Fi is switched off by the cable as before.
- **#91 Events: client › event › crew › card**: a client has many events, so the backup sheet now asks for the **event** between the client and the crew. Events are saved per client (newest first); a new event is typed with the on-screen keyboard, the field already holds today's date (`2026-11-28 `) so a name is typed after it or the date is changed. The files go to `<drive>/<client>/<event>/<crew>/<card>/`.
- **#89 Backups organised by client, crew and card**: *Backup* (the wizard of the Backup tab, and the one-tap backup on the home screen) first asks for the **client**, then the **crew**, then the **card**. The clients and crews are saved on the box and offered again (newest first, crews of other clients too), or a new one is added with the on-screen keyboard; the drive's folders are listed as well. A new client or crew gets its folder on the backup drive at once. The card is offered as the next number (*Card 1*, *Card 2* …), a card already backed up can be continued, or named freely. The files go to `<drive>/<client>/<crew>/<card>/…` instead of the folder named after the card. *Without client* keeps the old folders. Names are cleaned (letters, numbers, spaces, `- _ ( ) & . , '`; never a path). Only for the NVMe / USB backup drive; backups started by the OLED menu or the app are unchanged. `backup.py --target-folder "Client/Crew/Card 1"` does the work.
  - The keyboard is slimmer again so that the **OK** button of a dialog stays above it.
- **#87 Pictures and videos no longer depend on a web server URL for `/media`**: the Files viewer said "No preview available" for every JPG, although the preview and the file exist. The pages pointed at `/media/<drive>/…`, which the box's web server does not serve (only the file manager has that alias), so the thumbnail made during the backup and the original both failed to load. They now come through the API: `thumb` serves the thumbnail made during the backup as it is (else makes one), the new `file` action serves the file itself (with Range, so a video seeks) or as a download (`dl=1`). Only files below a mounted drive are served; `..` is refused. A picture that fails is written to `tmp/touch-js.log`.
- **#85 Opening a file shows it sharp**: the viewer of the Files tab showed the 480 px list thumbnail. It now follows with a 1600 px preview of the file made by the box (JPG, RAW, HEIC, TIFF, video frame), light enough for the Pi and sharp on the 800 x 480 screen. The support log `tmp/touch-js.log` also notes the first taps the page receives.
- **#83 The on-screen keyboard appears on the box**: a precedence slip (`$x = A or B` is `($x = A) or B`) switched the keyboard off whenever the setting existed in `config.cfg`, which is the case on every installed box, so it only worked on a box without the setting. Checked with the setting `True`, `true` and `false`.
  - **Support log:** errors of the pages in the box's own browser (it has no console), and a note when a file is tapped or the viewer opens, are written to `tmp/touch-js.log`.
- **#81 A keyboard that fits the box's small screen**: the keyboard covered 80 % of the 320 px high screen and hid the field it types into. Keys and rows are slimmer on a small screen, and a dialog with a field (Wi-Fi password, a name) moves to the top while the keyboard is open, so the field stays in view above it.
- **#79 Previews of pictures the box could not make one for**: a picture without a ready-made thumbnail got "No preview available" when ImageMagick failed or the web server may not read the file. The preview is now also tried with Pillow, a file the web server may not read is read as root (a preview only, nothing is changed), and the reason a preview fails is written to `tmp/touch-thumbs/errors.log` (ImageMagick's own message included). Earlier failures are tried again at once.
- **#77 On-screen keyboard that does not depend on the browser add-on; no Photos tab; the file preview says what it does**
  - **Keyboard:** the box's own screen now loads the keyboard (KioskBoard, bundled in `js/vendor/kioskboard`, MIT) from the pages themselves, for the Wi-Fi password and every other text field, also the ones that appear later. It follows the settings (keyboard on/off, language) and does not need the browser add-on, which did not show up on some boxes. A field never gets two keyboards. Slimmer keys on a small screen.
  - **No Photos tab:** the touch UI has Home, Backup, Log, Files, System. "Check the files" after a backup and the newest files on the home screen open the Files tab.
  - **Preview of a file (Files tab):** while the box makes the preview of a big picture or RAW file the caption says so; if it can not be made a picture the browser can show is shown as it is, else "No preview available" (the viewer was empty before). Other files show their name, size and date.
- **#75 The Bluetooth pairing code is a pill in the touch UI's status bar**: the 6-digit code for the Android app was only drawn on the OLED, so a box with a touchscreen and no OLED never showed it. The Bluetooth service now also leaves the code for the touch UI, which shows `Bluetooth code 048 213` in the top bar for as long as the phone asks for it (at most a minute).
- **#73 Update button; the Files tab for folders of thousands of files**
  - **Update (Settings):** looks on GitHub for a newer version (needs internet; says so when the box is offline), then downloads and installs it as a task with a log window, like a copy or a deletion. The screen restarts at the end. The installed version is written to `VERSION` by `install-touch-ui.sh` (an installation from before this has no version: the button then offers the latest).
  - **Files, no more pressing "Show more":** the next 300 files load by themselves when the end of the list comes into view; the bar shows which files are on screen (`701–1000 / 3000`); two buttons jump to the first and to the last files of a folder.
  - **Slimmer bars on the box's screen:** the drive row, the folder bar and the rows of the Files tab are smaller on a small screen, so the list has the room.
- **#71 True black in the dark theme**: the dark theme's background was a blue-grey (`#0f1216`), which on a backlit screen shows as grey. It is now black (`#000000`) with a slightly brighter text, so blacks are as deep as the panel can show them.
- **#69 Lighter pages while dragging**: shadows, blur and animations are switched off while a page is dragged, so every frame is cheaper to paint on the Pi.
- **#67 The full web interface scrolls by dragging without the browser add-on**: the classic pages now load the drag script themselves on the box's own screen (only for a browser on the box, not for phones or PCs), so text and elements are no longer selected while scrolling, whether or not the add-on is running.
- **#65 The drag script can never lock the page**: the page is only switched to "dragging" once a drag really moves, and a release that never arrives (button no longer held) ends the drag, so taps keep working.
- **#63 Dragging in the full web interface no longer selects or picks things, and is lighter**: the press itself is taken from the browser (no text selection, no dragging of links or pictures) and during a drag nothing is hovered or selected, so the big classic pages do less work per move.
- **#62 The full web interface scrolls without lag**: its stylesheet (bootstrap) sets `scroll-behavior: smooth`, so every position of the drag glided to its place a moment late. The drag script now switches that off in the pages of the box's screen.
- **#60 Scrolling by touch in every page, no red bar, invisible pointer actually applied**
  - **Cause of "nothing changed":** the kiosk user's home is private, so the kiosk tweaks and the boot-logo script checked its files as the installing user, found nothing and skipped the red bar, the pointer theme and the kiosk logo. They now check as the kiosk user.
  - **Scrolling:** the drag script is one shared file (`js/lbb-dragscroll.js`), used by the touch UI and by a small add-on of the kiosk browser (`lbb-touch-scroll@little-backup-box`, built by `install-kiosk-tweaks.sh`, installed through the browser policy next to the keyboard add-on) in every page, so the full web interface scrolls by finger too. The red bar is only hidden when the add-on is installed.
- **[#58](https://github.com/keeratsawhney/backupbox/pull/58) The Wi-Fi button shows the network name**: it showed the connection name of NetworkManager (`netplan-wlan0-Your Wedding Saga`, as netplan names a connection) and now the name of the network (`Your Wedding Saga`).
- **[#56](https://github.com/keeratsawhney/backupbox/pull/56) Smooth scrolling by dragging; the Wi-Fi box with a network cable**
  - **Scrolling:** moves once per frame (a screen that sends many events made it jerky) and keeps gliding after a flick, slowing down like on a phone; a slow drag stops where the finger stops, a new touch stops the glide.
  - **Wi-Fi box:** while a network cable is connected the box keeps the Wi-Fi radio off (file transfer mode), so the Wi-Fi box opened empty. It now says so and has a *Turn on Wi-Fi* button; the radio then stays on for 30 minutes (`cron_ip.sh`), a newly connected cable resets it.
- **[#55](https://github.com/keeratsawhney/backupbox/pull/55) The retained boot logo is removed again**: ending Plymouth with `--retain-splash` (#53) left a frame that showed through as lines and a faded double logo when the kiosk drew its logo over it. Updates remove the drop-in from boxes that got it.
- **[#53](https://github.com/keeratsawhney/backupbox/pull/53) The kiosk: no Pi desktop, the theme is kept, a plainer Wi-Fi box**
  - **No Pi desktop:** the kiosk user logs in to a plain `labwc` session (the Pi desktop session runs `labwc -m`, which adds the desktop wallpaper and panel to the kiosk start script); the boot logo is retained until the kiosk paints over it.
  - **Theme kept:** a theme picked on the box's own screen is saved in the configuration (`set_theme`, only from the box itself); the kiosk browser (a private window) forgot it at each start.
  - **Wi-Fi box:** a network row shows its name, a lock (password), a check (connected), the icon dimmer when the signal is weak, and a word only for connected or saved networks (no percentages, no security names); a shorter hotspot note.
  - `install-kiosk-tweaks.sh` keeps the red scroll bar until the touch UI that scrolls by dragging is installed.
- **[#51](https://github.com/keeratsawhney/backupbox/pull/51) The kiosk screen like the app: bigger text and buttons, no pointer, no red scroll bar, dragging scrolls**
  - `install-kiosk-tweaks.sh`: the page is scaled to the screen (shorter side about 320 px, e.g. 1.5× on 800×480; small screens stay as they are), a transparent pointer theme for the kiosk user, touch events on, scroll bars off (the original made a very wide red bar).
  - Touch UI: a mouse-style drag scrolls the list under it (a touchscreen that acts like a mouse could only scroll by the red bar); a drag from a button does not press it; real touch is left alone.
- **[#50](https://github.com/keeratsawhney/backupbox/pull/50) Screens on the DSI ribbon cable**: the installer made an SPI screen driver (`piscreen`) for every screen, which for a DSI screen is a display that isn't there. A connected DSI screen now gets driver `none` (new option in Settings → Screen): only `dtoverlay=vc4-kms-v3d`, the kernel finds the screen itself. The kiosk start script draws on the card of a connected DSI screen (it always took `card1`).
- **[#48](https://github.com/keeratsawhney/backupbox/pull/48) Boot screen with the logo, straight into the kiosk**: `install-boot-splash.sh` (Plymouth theme with the logo sized to the screen, no boot messages, cursor or rainbow screen; the kiosk session shows the same logo until the browser is up; a dark browser window). Run by the installers after the kiosk is set up; safe to run again; keeps `.lbb-backup` copies of the files it changes.
- **[#47](https://github.com/keeratsawhney/backupbox/pull/47) `install-touch-ui.sh` refuses on Bookworm before changing anything** (the scripts need Python 3.12+; on Bookworm it had already copied them over an old installation when it failed, leaving it half converted).
- **[#45](https://github.com/keeratsawhney/backupbox/pull/45) Deleting: progress window with free space; deleted folders stay deleted**
  - **Why folders came back:**
    - the previews job could make a deleted folder again (it created missing parent folders for thumbnails): fixed, a deleted file or folder is left alone;
    - a big folder took longer than a web request may (about 30 s) and was cut off half way: deleting is now a task on the box (`lib_delete.py`).
  - **Window:** a bar, *N of M files*, how much was deleted and the **free space** (also before and after in the log: `64.1 GB -> 64.3 GB (+165 MB)`), so you can see that it is gone. The list behind it refreshes when the task ends; a task still running is shown again when you open the Files tab.
  - **Checked:** after the deletion every path is looked at again, what is still there is deleted once more and reported (`NOT deleted: name` with the reason, e.g. a drive with errors). Links are removed, never what they point to.
  - Deleted files also leave the photo database of the drive and the list of previews still to do, and a deleted photo's thumbnail goes with it.
  - The copy window has the same bar and free space of the destination; no stray `null` in the task window.
- **[#44](https://github.com/keeratsawhney/backupbox/pull/44) Copy to any drive from the Files tab, back gesture, app with Wi-Fi off**
  - **Files tab, copy:** select folders and files (long-press), tap the copy icon, choose a drive and a folder (new folders can be made) and *Copy here*. The box copies in the background (`lib_copy.py`, progress in the task sheet), checks every file afterwards and keeps an older version of a changed file in `_replaced`. It checks the free space first and never copies a folder into itself. A drive that is opened read only is writable only for the copy.
  - **Files tab, back:** every folder and drive is a step in the history, so the back gesture (and the app's back button) goes back folder by folder; a reload keeps the folder.
  - **Files tab:** the *Show more* button is centred.
  - **App, Wi-Fi off:** it says so instead of "no box found", opens Android's Wi-Fi panel (apps can not switch Wi-Fi on themselves since Android 10) and searches when the phone is connected. *Open box* over Bluetooth does the same.
- **[#42](https://github.com/keeratsawhney/backupbox/pull/42) Complete copies, proven file by file; all files listed**
  - **Check after every backup** (`lib_verify.py`): every file of the card is looked up on the backup drive by name, size and date. The summary shows *N files verified* or *N of M not copied!*; the app's System page shows *Last backup check*; `tmp/verify-last.json` lists the files. By hand: `sudo python3 lib_verify.py`.
  - **Copy:** a file is the same only if name, size AND date match (it was name and size: a new photo that reused a name and had the same size, e.g. uncompressed raw, was skipped). Daylight saving time (FAT) is tolerated. The exclusion `*trash*` (which hid e.g. a folder `trash_the_dress`) is replaced by the exact names of the trash folders.
  - **Files tab:** folders open in pages of 400 with *Show more* and the folder's total (it stopped at 3000 entries without a hint).
  - **Photo views:** `.HIF` (Sony HEIF), more raw formats (`arq`, `crm`, `erf`, `iiq`, `mef`) and videos (`mov`, `m4v`, `mts`, `m2ts`, `mxf`, `mkv`, `3gp`, `mpg`); the folder `_replaced` with older versions of replaced files is left out.
- **[#41](https://github.com/keeratsawhney/backupbox/pull/41) Every card in its own folder, no file ever overwritten**
  - **Fix:** the old card IDs made of size and file system only (`lbb_119.3G_exfat_1.0`) were the same for every card of that size. Their photos met in one folder, where files of the same name were skipped or overwritten.
  - **Such cards get their own folder** (date, time, card name) on their next backup, and the whole card is copied into it. Locked cards: `card_<UUID>`, stable until the card is formatted.
  - **The same card shot further:** the same folder, only the new files are copied.
  - **Never overwritten:** a different file of the same name on the card (photo numbers used again) moves the older copy on the SSD to `_replaced/<date>` instead of overwriting it.
- **[#40](https://github.com/keeratsawhney/backupbox/pull/40) Cable straight from the box to a computer**: when no router answers within 30 s, the box hands out addresses itself (box `10.42.0.1`). With a router, the router's address as before.
- **[#39](https://github.com/keeratsawhney/backupbox/pull/39) Fix: the display stayed off after an update** (#37 restarted it with a call that sends nothing while the address is unchanged).
- **[#38](https://github.com/keeratsawhney/backupbox/pull/38) Fix: Finder copies from the network share failed (error 100060)**: the share stored Mac metadata in extended attributes, which exFAT drives don't have. Plain files now; SMB multichannel off (unreliable with Macs that have Wi-Fi and Ethernet).
- **[#37](https://github.com/keeratsawhney/backupbox/pull/37) OLED home screen up to date right after network changes**
  - Any network change (Wi-Fi or cable connected or lost, internet found) redraws the home screen with the new address and online state at once, not after up to a minute. It no longer says "offline" for the first minute after boot.
  - An update restarts the display, so new display code runs without a reboot.
- **[#35](https://github.com/keeratsawhney/backupbox/pull/35) Card folders named by date, folder dates kept, LAN address on the OLED**
  - New cards (or cards formatted in the camera) get a folder named by the date and time of their first backup and the card's name, e.g. `2026-11-14_15-29-07_NIKON_Z_6_2`. Cards backed up before keep their folder.
  - Thumbnails no longer change the photo folders' modified date.
  - Ethernet: the OLED shows the cable's address. Comitup is paused while the cable is in, and every minute the box checks that the Wi-Fi is off with a cable and on without one.
- **[#33](https://github.com/keeratsawhney/backupbox/pull/33) Ethernet file transfer mode**
  - **Wi-Fi:** off while an Ethernet cable is connected, back on when it is unplugged (NetworkManager dispatcher).
  - **OLED home screen:** *File transfer* with the address, the link speed and the share login (`lbb · password`).
  - **Network share:**
    - the backup drive stays mounted while the box is idle, so it shows in `\\box\media`;
    - user `lbb` with a share password shown in the app when the box has no password (Windows 10/11 refuse guest access);
    - Samba tuned for gigabit (sendfile, async I/O, SMB2+).
  - **App, System page:** Ethernet link speed, the share's address and login.
- **[#31](https://github.com/keeratsawhney/backupbox/pull/31) Fix: background previews stopped at once**: the end of the backup unmounted every drive, including the one the background job works on. It now stays mounted until the job is done. The job's errors go to `tmp/background/errors.log`.
- **[#30](https://github.com/keeratsawhney/backupbox/pull/30) Backups report done right after copying; thumbnails and database in the background**
  - `background.py` makes the thumbnails and the database entries at low priority. The list of files to do is kept on the drive, so a power off only interrupts it.
  - The app's top bar shows a *Previews 312/2418* pill while it works.
  - Not used when the box powers off after the backup, a cloud backup follows, or EXIF updates are on: then everything runs before "done", as before.
  - Thumbnails in their own module (`lib_thumbnails.py`): JPEGs decoded at about 1/4 size (about 2× faster), turned while scaling.
  - Fix: converted HEIC images were not queued for thumbnails (wrong list name).
- **[#29](https://github.com/keeratsawhney/backupbox/pull/29) Fan at full speed from 60 °C** (Raspberry Pi 5 Active Cooler; the default reaches full speed at 75 °C): `install-fan.sh`, run by the installer and the update.
- **[#28](https://github.com/keeratsawhney/backupbox/pull/28) App finds the box on a home Wi-Fi during backups, faster thumbnails**
  - The app's box search uses a quick check that the box answers at once, also while a backup keeps it busy (the full status took too long, so the box was not found).
  - If https does not answer, the app opens the box over http on port 8080, like a browser (never after a refused certificate).
  - **Open box** over Bluetooth opens the box's address in the Wi-Fi network when it has no hotspot.
  - Thumbnails: one exiftool kept running per worker instead of two exiftool starts per RAW file; one ImageMagick thread per worker.
- **[#27](https://github.com/keeratsawhney/backupbox/pull/27) Faster "Sync database", RAW previews the right way up**
  - The database step after a backup reads photos in groups of 50 with one exiftool run, about 15× faster than one run per photo.
  - Quick previews of RAW files (shown while a backup still runs) are turned like the photo.
- **[#23](https://github.com/keeratsawhney/backupbox/pull/23) App over Bluetooth + Wi-Fi, box links open the app, OLED home screen fixes**
  - **Bluetooth service on the box** (`lib_ble.py`): status, start (copy only) and stop, power off, and the Wi-Fi details. It pairs with a code shown on the OLED.
  - **App:**
    - pairs through Android's device popup;
    - shows a status card over Bluetooth;
    - **Open box** joins the box's hotspot by itself.
  - **Links:** the box's address on Android opens the app, with the browser as fallback.
  - **OLED:**
    - every screen returns to the home screen (8 s; 60 s after a backup; never during one);
    - the home screen survives display restarts;
    - the touch UI viewer's download button keeps clear of the status bar.
- **[#22](https://github.com/keeratsawhney/backupbox/pull/22) Android app: Backup Box (touch UI in an app)**
  - Finds the box: last used, hotspot, network search, or a typed address.
  - Stays on the box's Wi-Fi without internet.

  - Downloads go to the gallery.
  - GitHub builds and publishes the APK; the signing key comes from secrets.

  - Graphic menu with icons, selection bar, confirm dialogs and status page.
